# Заметки по реализации

## Текущее состояние

Реализованы все три основных функциональных блока задания:

- генерация синтетических кандидатов и одностраничных PDF-резюме с фотографиями;
- индексация PDF в Elasticsearch со структурированными полями и локальными embeddings;
- поиск по полям, semantic search и CLI-чат с агентом, который вызывает Elasticsearch tools.

Также добавлен фиксированный eval-датасет из десяти PDF, manifest с пятью кейсами и
скрипт, который печатает результаты `PASS/FAIL`.

## Что не успела сделать

### Тесты

Тесты не добавлены. В задании указано требование минимум двух тестов без API-ключа,
но за отведённое время я не успела определить и реализовать полноценную тестовую
стратегию.

Два небольших unit-теста сами по себе дали бы минимальную проверку отдельных
функций, но не покрыли бы важные сценарии проекта: генерацию запросов к
Elasticsearch, обработку пустых результатов, работу CLI и взаимодействие chat-агента
с tools. Поэтому тесты были оставлены на следующий этап, чтобы не добавлять формальное
покрытие без практической пользы.

### Архитектурный рефакторинг

Код организован по функциональным областям, но отдельные части можно разделить
лучше. В частности, дальше стоит:

- отделить CLI-координацию от application services;
- выделить отдельные интерфейсы для LLM-провайдера, image-провайдера и embedding-модели;
- унифицировать обработку ошибок и конфигурации;
- разделить chat tools и низкоуровневые Elasticsearch-запросы;
- вынести форматирование результатов поиска и eval-логику в отдельные модели;
- добавить явные dependency boundaries между генерацией, индексацией, поиском и чатом.

## Что делала бы дальше

1. Зафиксировала тестовую стратегию и добавила API-free unit-тесты для поиска,
   валидации CLI и обработки пустых результатов.
2. Добавила интеграционные тесты с mock Elasticsearch для indexing/search pipeline.
3. Добавила проверку того, что chat-agent действительно вызвал tool перед ответом.
4. Провела архитектурный рефакторинг и уменьшила связанность модулей.

## Ограничения

- Для работы генерации, извлечения полей и chat-агента нужен API-ключ текстовой модели.
- Embeddings создаются локально через `sentence-transformers`.
- Elasticsearch запускается локально через Docker Compose.
- Eval-скрипт выполняет реальные запросы к модели и расходует API-бюджет.
